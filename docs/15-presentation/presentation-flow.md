# Presentation Flow

## Presentation Structure

| Section | Time | Content |
|---|---|---|
| Introduction | 1 min | Project name, team, problem statement |
| Background | 1 min | What is infrasound, why it matters |
| Solution Architecture | 2 min | System overview, hardware + software + AI |
| Technical Deep Dive | 3 min | Key engineering decisions, signal processing, AI |
| Live Demo | 3 min | See [Judge Demo Flow](../14-demo/judge-demo-flow.md) |
| Results | 1 min | Calibration/testing results (what was measured) |
| Future Scope | 1 min | Roadmap, scalability, advanced AI |
| Q&A | 3 min | Prepared for anticipated questions |

## Key Messages

1. **Infrasound monitoring is important** but currently expensive and inaccessible
2. **We built a low-cost prototype** that combines hardware, signal processing, and AI
3. **The AI is appropriate** — unsupervised anomaly detection, not fabricated classification
4. **We demonstrate honestly** — no fake numbers, clear assumptions, known limitations
5. **The system works end-to-end** — from atmospheric pressure to dashboard alert

## Slide Guidelines

- Use diagrams and flowcharts heavily (from the documentation)
- Show the actual dashboard
- Include the live demo
- Avoid walls of text
- Use the architecture diagrams from Section 02 as visual anchors
